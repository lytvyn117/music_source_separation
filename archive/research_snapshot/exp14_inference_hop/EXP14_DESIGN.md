## Inference and scoring

Exp10 `config.json` specifies a 176,400-sample chunk and an 88,200-sample hop. Its `validation.py` passes 50% overlap to `chunk_starts`. Exp14 passes 50% for A and 75% (44,100 samples) for B to the same function. That function appends a full window aligned to the end of the song when needed. `chunk_batch` keeps its right-zero-padding rule for songs shorter than a chunk. All 16 songs are longer than a chunk. The separator retains the same internal STFT window, padding, fixed scaling and inference-only FP32 compute. The overlap-add weights are the same positive Hann samples in both arms. Output is divided by the sum of the weights actually applied at each sample. Instrumental output is the original mixture minus the reconstructed vocals. The two settings can change chunk positions and overlap-add weight sums under these same rules.

- Reuse the Exp10 reconstruction primitives and `song_metrics`. Calculate vocal SI-SDR with the same `compute_framewise_metrics` function that the archived evaluator already uses to compute SDR. Both are medians over complete 1-second frames above −45 dBFS. Instrumental SDR uses instrumental activity. Side SDR uses whole-song `(L−R)/2` and the archived −50 dBFS reference-side gate. Absolute bleed is the absolute projection of instrumental error onto true vocals, expressed as 100 times the coefficient. Mixture consistency is the song's maximum absolute error in full-scale units, checked against Exp10's `2e-5 × max(1, peak(abs(mix)))` limit.
- Use batch size one with FP32, autocast disabled, deterministic algorithms, TF32 matmul disabled, and the archived efficient-attention/math SDPA backends. Run Raw A, Raw B, EMA B, EMA A in one process and preserve the frozen song order within each arm. Use one untimed synthetic 4-second warmup per arm. CUDA-synchronized inference timing includes chunking, transfers, forwards, overlap-add and residual synthesis. It excludes reading references, warmup and scoring. Record peak PyTorch CUDA allocated and reserved memory per song and per arm. Reserved memory includes allocator caching within an arm. Report total inference time and arm peak memory as well as per-artist means.
- Compare the fresh A measurements against the archived 2-second Exp10 rows for both weight sets, including exact UUID order, chunk counts and active-frame counts. Use absolute tolerance 1e-6 for the archived floating-point metrics. Evaluate all songs, keep every pair and require finite predictions and metrics. Report B minus A, with lower values preferred for bleed, mixture error, time and memory. Artist summaries average each artist's songs. Artist-macro averages the seven artist means equally. Give group improvement counts by metric. Use the archived 0.01 dB tie margin for dB metrics and report other metric signs at stored precision. Give descriptive percentile intervals from 10,000 paired artist bootstrap draws with seed 42.

## Decision recorded before inference

- Apply the requested regression limits to the artist-macro deltas for both weight sets: vocal and instrumental SDR each at least −0.05 dB, absolute bleed at most +0.5 percentage points. For stereo, apply the same −0.05 dB floor to each side SDR. Predictions and metrics must be finite, with every song passing the archived mixture-consistency check.
- Treat a Raw gain larger than 0.05 dB in vocal or instrumental SDR, or a Raw reduction larger than 0.5 percentage points in absolute bleed, as meaningful. These practical margins use the size of the requested regression limits. Require an improvement on that same metric for at least five of seven Raw artist groups and directional support from EMA, defined as a favorable EMA macro delta and at least four of seven EMA artist groups improving. These interpretation choices were set for Exp14. Report vocal SI-SDR and stereo changes alongside the decision.
- Use `ADOPT_1S_HOP` when the quality and consistency rules pass. Use `KEEP_2S_HOP` when the valid comparison fails a regression limit, shows insufficient benefit with the faster 2-second hop, or reveals numerical instability isolated to B. Use `INCONCLUSIVE` when provenance, archived A parity or paired coverage fails, or the runtime and quality evidence gives no supported choice under these rules.
